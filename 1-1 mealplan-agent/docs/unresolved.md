# 미해결 과업 분석

- 미션: AI Agent에게 일 제대로 시키는 법 배우기
- 대상: 밀플랜 매니저 / Gemini 4 Hydrogen
- 상태: STEP 07 학습자 최종 선정 및 분석 확정
- 실험 조건: 일반 Chat, Low, Plus(학습자 보고), 외부 도구 미사용 지시. v1과 v2는 각각 신규 채팅 첫 사용자 메시지로 적용.

## UNR-002. 구매 비용 합산 및 예산 검증

- 관련 기준: E05, E06
- 실제 사용 프롬프트: PROMPT-001 v1.1 전문(부록 A), [v1](../prompts/system-prompt-v1.md), [v2](../prompts/system-prompt-v2.md), 조건 변경 요청(부록 B).
- 개선 시도: v1에서 비용 합산 및 예산 검증 규칙을 추가, v2에서 행별 비용·분류별 소계·교차 검산과 실패 처리 규칙을 강화.

| 실행 | AI 제시 합계 | 독립 검산 | 절대 오차 |
|---|---:|---:|---:|
| EXP-001 | 163,000 | 162,800 | 200 |
| EXP-002 T04 | 156,900 | 156,500 | 400 |
| EXP-002 T26 | 139,900 | 144,000 | 4,100 |
| EXP-003 T04 | 132,400 | 145,200 | 12,800 |
| EXP-003 T08 | 124,900 | 137,700 | 12,800 |

단위 원. EXP-003 T08 실제 응답 발췌:

> **분류 소계 총합**: 16,500 + 53,000 + 26,100 + 25,300 + 5,300 + 11,500 = **124,900원** (전체 행 합산과 완전 일치)

독립 합산 137,700원. 예비비 15,000원을 포함하면 152,700원으로 배정 한도 150,000원을 2,700원 초과한다. 구매 목록 자체는 한도 이내이나 누락 비용 미포함. T10에서도 124,900원 및 가용 잔액 10,100원 반복. 실제 가용 잔액은 -2,700원이다.

### 학습자 직접 작성 미해결 이유 (원문)

LLM이 계산 규칙을 이해하고 설명하는 것과 실제로 정확한 산술 계산을 수행하는 것은 별개의 문제입니다.

이번 실험에서는 검산 방법을 추가했지만, AI가 생성한 검증 결과를 독립적으로 강제 확인하는 장치가 없었습니다. 따라서 잘못된 합계도 검산 완료 상태로 출력될 수 있었습니다.

이는 관찰된 결과를 기반으로 한 원인 가설이며, 모델 내부의 실제 계산 과정까지 확인한 것은 아닙니다.

### 향후 해결 방안 (학습자 원문)

AI가 생성한 검증 결과를 독립적으로 강제 확인 하네스 적용이 필요하다고 판단됨

상태: 미해결. 구조화된 구매 데이터를 외부 계산 엔진으로 검증하고 실패 시 수정하도록 통제하는 방안은 미구현 제안이다.

## UNR-003. 전체 식재료 산출 완전성

- 관련 기준: E03, E05
- 실제 사용 프롬프트: PROMPT-001 v1.1 전문(부록 A), [v1](../prompts/system-prompt-v1.md), [v2](../prompts/system-prompt-v2.md), 조건 변경 요청(부록 B).
- 개선 시도: v1에서 반찬 및 양념까지 포함하도록 지시, v2에서 끼니 ID와 식재료 원장 및 전 품목 대응 규칙 도입.
- 실제 결과: Zero-shot 김치·깍두기·단무지 누락, v1 건미역·애호박·깍두기·오이피클 등 구매 누락, v2 원장 자체 누락 지속.

EXP-003 T04 실제 응답 발췌(식단표와 원장):

> | **화** | 화-아침 | 가정식 | 누룽지 숭늉, 계란후라이, 김치, 김 | 15분 | 간편식 |
>
> | 화-아침 | 계란후라이 / 밥 / 김 | 쌀 | 400 | g |
> |  |  | 달걀 | 5 | 개 |
> |  |  | 김 | 1 | 팩 |

누룽지와 밥의 관계를 명시하지 않았고 김치가 누락되었다. T08에서도 김치, 깍두기, 부추, 육수, 구체적 밑반찬 등이 원장 또는 구매 목록에 반영되지 않았다. 원장 내부 집계 성공과 실제 메뉴의 완전성은 별개이다.

### 학습자 직접 작성 미해결 이유 (원문)

v2에서는 식재료 원장을 기준으로 계산하는 구조를 도입했습니다. 하지만 식단표에 있는 모든 메뉴가 원장에 완전하게 반영되었는지를 확인하는 절차가 충분하게 작동하지 않았습니다.

### 향후 해결 방안 (학습자 원문)

메뉴별 표준 레시피 데이터베이스와 식재료 완전성 검증 절차를 도입하는 방식을 검토합니다.

상태: 미해결. 제안한 DB 및 검증 절차는 미구현이다.

## 부록 A. 실제 공통 과업 프롬프트 전문 (두 과업 공통)

다음 사용자 조건을 바탕으로 일주일 식단 스케줄과 장바구니 구매 목록을 작성해 주세요.

## 1. 사용자 조건

- 가족 구성: 성인 2명, 자녀 3명
- 식단 계획 기간: 월요일부터 일요일까지 7일
- 식재료 구매 예산: 200,000원
- 외식 비용은 식재료 구매 예산에 포함하지 않음
- 식단 범위: 평일 아침·저녁, 주말 아침·점심·저녁
- 선호 식단: 한식 위주, 일부 양식 포함
- 한 끼 최대 조리 시간: 30분
- 알레르기 및 제외 식품: 미확정
- 외식 일정: 토요일 저녁

## 2. 현재 보유 식재료

- 쌀: 3kg
- 달걀: 10개
- 대파: 3개
- 양파: 2개
- 감자: 3개
- 깐마늘: 10개
- 고추: 3개
- 두부: 1모
- 기본 양념류: 보유, 상세 품목 및 수량 미확정

## 3. 과업 요구사항

- 가족 구성과 식사 일정을 반영한 일주일 식단을 계획해 주세요.
- 보유 식재료를 최대한 활용해 주세요.
- 메뉴별로 필요한 식재료와 수량을 산출해 주세요.
- 보유 식재료를 반영하여 추가 필요량과 실제 구매 수량을 결정해 주세요.
- 식재료 구매 비용이 예산 범위 내에 있도록 계획해 주세요.
- 식재료 손질부터 조리 완료까지 한 끼 전체 준비 시간이 30분 이내가 되도록 식단을 구성해 주세요.

## 4. 출력 규격

다음 다섯 가지 결과를 Markdown 표와 텍스트로 작성해 주세요.

1. 주간 식단표
   - 요일, 아침, 점심, 저녁, 끼니별 예상 조리 시간
2. 식재료 소요량
   - 메뉴별 필요 식재료 및 수량
   - 식재료별 주간 총소요량
3. 재고 분석표
   - 식재료명, 총소요량, 보유량, 추가 필요량
4. 장바구니 목록
   - 분류, 구매 품목, 실제 구매 수량, 가정한 단가, 예상 비용
5. 조건 충족 검토
   - 총예산, 예상 구매 비용, 잔여 예산
   - 사용자 조건 충족 여부
   - 가정한 사항 및 확인이 필요한 사항

## 5. 실행 조건

웹 검색 및 외부 도구를 사용하지 말고 제공된 정보를 바탕으로 작성해 주세요. 실시간 가격이 아닌 경우에는 추정 가격임을 표시해 주세요.
